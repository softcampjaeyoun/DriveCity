# 7개 구(서초·강남·송파·강동·광진·용산·성동) 확장 계획: 타일 스트리밍

약 200km² 는 지금 구조(맵 전체를 한 번에 로드)로는 불가능해요. 건물 10만 동 이상, 도로 3,000km 가 넘어 브라우저 메모리와 그리기 양을 넘겨요. 플레이어 주변만 불러오는 구조가 필요해요.

## 데이터

- `tools/fetch-osm.mjs` 가 이미 2.2km 타일로 나눠 받아요. 7개 구 bbox (대략 37.46~37.56, 126.95~127.17) 는 타일 약 100개. Overpass 혼잡도에 따라 1~3시간.
- `tools/build-map.mjs` 를 타일 단위 출력으로 바꿔요: `public/map/seoul/{tx}_{tz}.json` + `index.json` (원점·타일 크기·타일 목록). 좌표 원점은 전체 공통.
- 도로 그래프는 타일 경계에서 끊기므로, 경계 노드에 `link: { tile, nodeId }` 를 적어 두고 런타임에서 이어 붙여요.

## 런타임

- `world/tiles.ts`: 플레이어 주변 3×3 타일을 유지. 새 타일 진입 시 다음 타일을 `fetch` 하고 워커에서 파싱 → 메인 스레드에서 `buildCity(tile)` 로 메시 생성(프레임당 한 재질씩 나눠 끊김 방지). 멀어진 타일은 `dispose`.
- 그래프: 로드된 타일들의 노드·간선을 하나의 `RoadGraph` 로 병합(인덱스 오프셋). 경로 탐색은 로드된 영역 안에서만. 라이벌·경찰은 로드된 타일 안에서만 생성·이동하고, 타일이 내려가면 제거.
- 교통: 타일마다 대수를 배정(도로 길이 비례), 타일이 내려가면 그 차들도 제거.
- 미니맵: 타일별로 미리 그린 PNG(빌드 때 생성) 를 그리드로 깔기. 큰 지도는 축소본 한 장(전체 2~4k px).
- 충돌: 타일별 공간 해시.

## 순서

1. build-map 타일 출력 + index (1일)
2. tiles.ts 로드/해제 + 그래프 병합 (2일)
3. 교통·미션·미니맵 타일 대응 (1일)
4. 7개 구 수집·검증 (수집 대기 시간 포함 1일)

지금 한 번에 로드하는 강남·서초 핵심(34km²) 이 단일 맵의 상한선이에요. 그 이상은 이 계획으로 가요.
